# データエンジニア

## 役割

市場データの取得・整形・永続化。**Phase 1 の中心的な担い手。**

## 担当モジュール

| モジュール | 内容 | Stage |
|---|---|---|
| `data/jquants.py` | J-Quants V2 日足・**日付指定の銘柄一覧** | A |
| `data/yahoo.py` | **yfinance 日足・分足（口座不要）** | A |
| `data/calendar.py` | 営業日・決算発表日カレンダー | A |
| `data/store.py` | ローカルデータストア（Parquet + SQLite） | A |
| `data/recorder.py` | 分足のリアルタイム蓄積（WebSocket → Parquet） | **B** |
| `data/shortable.py` | 一般信用売建可能銘柄・空売り価格規制 | **B** |

## Stage A（現在）— 口座もAPIも不要

**`data/yahoo.py` と `data/jquants.py` が Phase 1 の中心。**

### yfinance の取得可能期間（Yahoo の制限）

=========  ==============
足         遡れる期間
=========  ==============
1分足      **直近7日**
2〜90分足  **直近60日**
日足       制限なし
=========  ==============

**Phase 1 の最初に、実機でこれを実測して確認すること。**
サンドボックスではネットワークポリシーにより未検証。

- **5分足は過去60日分をまとめて取れる** → 竹の検証をすぐ始められる
- **1分足は7日窓** → 日次でローリング回収して蓄積する

### J-Quants で必ず押さえること

**日付指定の上場銘柄一覧**を取得できること。
サバイバーシップバイアスの回避に必須で、yfinance では代替できない
（`docs/03-universe.md` §4.2）。

### 期間制限を超えた指定は黙って切り詰めない

エラーにすること。**取れたつもりで欠損している**のが最悪のケース。
バックテストの前提が静かに壊れる。

## 守ること

1. **認証情報をコードに書かない。** `.env` から環境変数経由でのみ読む
2. **API のレート制限を守る**（J-Quants・kabuステーションAPI ともに）
3. **取得したデータをそのまま信用しない。** 欠損・異常値・重複を検出する
4. **データファイルをコミットしない。** `data/` は `.gitignore` 済み
5. **再取得可能にする。** 同じ日付を再取得しても壊れない冪等な設計にする

## データ品質チェック

取得したデータに対して最低限：
- 営業日なのにデータがない銘柄がないか
- 前日終値から異常に乖離していないか（分割・併合の未調整を検出）
- 出来高0のバーが連続していないか
- 時刻の重複・欠落がないか

**異常を見つけたら黙って修正せず、報告する。**
データの異常は戦略の前提を壊すため、人が把握しておく必要がある。
