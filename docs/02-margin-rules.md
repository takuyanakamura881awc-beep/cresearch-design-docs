# 02. 信用取引ルールとレバレッジ1倍の不変条件

本プロジェクトの中核となる設計方針と、それが生むリスクの扱いを定義する。

---

## 1. 不変条件 — レバレッジ1倍固定

```
建玉総額（買建 + 売建の合計） ≤ 現金残高
```

**この式をコードで強制する hard limit とする。** `risk/leverage.py` を
全発注の必須通過点に置き、バイパス経路を作らない。

### なぜ信用取引を使うのか（現物ではなく）

現物には**差金決済規制**がある。同一銘柄を同日に
「買い → 売り → **同じ資金で**再び買い」ができない。売却代金は「日計り取引拘束金」として
拘束され、同一銘柄の当日再買付には使えない（別銘柄への当日買付は可能）。

**帰結: 現物では1銘柄あたり実質1日1回転が上限。デイトレードの資金効率に天井ができ、
スキャルピングは原理的に成立しない。**

信用取引ならこの制約が消える。

### 得るもの

| メリット | 内容 |
|---|---|
| **同一銘柄の当日複数回転** | 差金決済規制の回避。資金効率が大幅に向上 |
| **空売り** | 下落局面でも収益機会。ロング/ショート両建てで相場環境への依存を減らせる |
| **手数料0円・金利0%・貸株料0%** | デイトレ信用の条件。実質コストはスリッページとスプレッドのみ |
| **オーバーナイトリスクなし** | 当日決済。場が閉じている間の暴落・材料に晒されない |

### 失うもの・増えるリスク

| リスク | 評価 |
|---|---|
| 追証 | **ほぼ消える。** 委託保証金率が実質100%。追証ラインは維持率20%割れ。最低委託保証金30万円も50万円でクリア |
| **空売りの損失無限大** | **残る。** 上昇に上限がないため。→ 逆指値ストップを絶対条件にする |
| **当日決済失敗のペナルティ** | **残る。** §3 で詳述 |

> レバレッジ1倍を守る限り、最大損失は現物と同等。
> **この不変条件をコードで守り抜くことが、本システムのリスク管理の中核。**

---

## 2. 委託保証金のルール

| 項目 | 規定 | 本プロジェクトの状態 |
|---|---|---|
| 最低委託保証金 | 30万円以上 | 50万円 → **クリア** |
| 委託保証金率 | 約定代金の30%以上 | レバ1倍なので**実質100%** |
| 追証ライン | 維持率20%割れ、または保証金30万円割れ | **極めて遠い** |

レバレッジ1倍運用では保証金率が実質100%になるため、
追証が発生するには建玉が80%下落する必要がある。現実的には起こらない。

**ただし保証金30万円割れのラインは注意。** 累積損失で総資産が30万円を下回ると
信用取引そのものが継続できなくなる。ドローダウン上限-15%（05 #6）は
このラインへの到達をはるかに手前で止める役割も持つ。

---

## 3. デイトレ信用の当日決済 — 最重要の実装要件

デイトレ信用（一般信用・日計り）の建玉は**当日中に必ず返済**しなければならない。

**返済しなかった建玉は翌営業日に強制決済され、
1注文につき2,200円（税込）の手数料が発生する。**

### なぜ致命的か

月利5%の目標は**1日あたり約1,220円**の利益（50万円 × 0.244%）。

**強制決済1回で約2日分の利益が消える。**

### 帰結: 大引け前の全建玉クローズはシステムのクリティカルパス

`execution/close_all.py` を最重要コードパスとして扱う：

1. **14:50**（暫定、要調整）に無条件で全建玉を成行クローズ
2. クローズ完了を `GET /positions` で**必ず突合確認**
3. 残っていれば**再試行 + アラート**
4. API障害・PC障害に備え、**手動の全手仕舞いスクリプトを常備**
5. **ペーパートレード期間中も同じロジックを毎日走らせ、実績で信頼性を検証する**

### 大引けと緊急停止でコードパスを共用する

`close_all.py` は大引けの定時クローズと、キルスイッチ・損失上限による
緊急クローズの**両方から呼ばれる**。最も重要なコードを1本に集約し、
ペーパー期間中に毎日実行することで信頼性を稼ぐ。

> 実行時刻 14:50 は暫定値。大引け直前は板が薄くなりスリッページが増えるため、
> ペーパー期間の実測で調整する（09 未決事項）。

## 4. 空売りの扱い

### 4.1 逆指値ストップを絶対条件にする

**ショート建玉はストップ注文なしでは1秒も保持しない。**
上昇に上限がない以上、損失も理論上は無限大。レバ1倍でもこの性質は変わらない。

エントリー注文とストップ注文はセットで送り、ストップの発注失敗時は
**建玉を即座に手仕舞う**。

### 4.2 売建できる銘柄は限られる

制度信用では売建できない銘柄でも、一般信用（デイトレ）なら売建可能なものが多数ある。
ただし**在庫次第**で日々変動する。

→ `data/shortable.py` で**日次に売建可否を取得**し、ユニバース構築の
ハードフィルタに使う（03-universe.md フィルタD）。

### 4.3 空売り価格規制

直近公表価格から一定以上下落した銘柄には価格規制がかかり、発注が弾かれる。
**発注前チェックに組み込む**（05-risk-management.md #12）。

### 4.4 逆日歩

制度信用の売建では逆日歩（品貸料）が発生しうる。
**デイトレ信用（一般信用・当日決済）なら受渡日をまたがないため、原則発生しない。**
これも当日決済を徹底する理由のひとつ。

## 5. コスト構造

| 項目 | デイトレ信用 |
|---|---|
| 取引手数料 | **0円** |
| 買方金利 | **0%** |
| 貸株料 | **0%** |
| 逆日歩 | 原則なし（当日決済のため） |
| **スリッページ・スプレッド** | **発生する。これが実質コスト** |
| 強制決済ペナルティ | 2,200円/注文（**発生させない前提**） |

> **手数料が0でもコストは0ではない。**
> バックテストとペーパートレードでは、スプレッド・スリッページ・約定遅延を
> 必ずモデル化する。甘く見積もると本番で必ず乖離する。
