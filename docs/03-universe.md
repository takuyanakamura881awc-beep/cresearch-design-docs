# 03. 銘柄選定

銘柄選定は**2層構造**にする。重い計算（流動性・信用区分）を日次バッチで済ませ、
寄り前の限られた時間（8:00-8:55）には軽いスコアリングだけを走らせるため。

```
東証プライム 約1,600銘柄
   │
   ├─ Layer 1: ユニバース構築（日次バッチ・ハードフィルタ）
   │     └─→ 100〜200銘柄
   │
   └─ Layer 2: 日次スコアリング（寄り前・WebSocket 50枠）
         └─→ 50銘柄を監視
               └─→ シグナル発生 3〜5銘柄にエントリー
```

---

## 1. Layer 1 — ユニバース構築（日次バッチ、寄り前に実行）

取引対象になりうる母集団を機械的に絞る。すべてハードフィルタ（該当したら無条件で除外）。

| # | フィルタ | 条件 | 理由 |
|---|---|---|---|
| A | 市場 | 東証プライム | グロース・スタンダードは流動性とボラが極端 |
| B | 流動性 | 20日平均売買代金 **≥ 10億円** | 10〜15万円の注文が板を動かさない水準を確保 |
| C | **株価レンジ** | **300円 〜 3,000円**（2段階運用、§2） | 単元100株と50万円の資金制約 |
| D | 信用区分 | **一般信用（デイトレ）売建可能銘柄** | ショートを使うため |
| E | 空売り規制 | 価格規制がかかっていないこと | 発注が弾かれる |
| F | 決算 | 決算発表日の前後1〜2営業日を除外 | ギャップリスクが予測不能 |
| G | 上場期間 | 上場後3ヶ月未満を除外 | 値動きの統計が取れない |
| H | 特殊状態 | ストップ高/安・売買停止・監理/整理銘柄を除外 | 約定不能・異常値 |
| I | コーポレートアクション | 株式分割・併合の前後を除外 | 価格の連続性が壊れる |

**通過数の見込み**: 約1,600 → 流動性(B)で300〜400 → 株価レンジ(C)で150〜250
→ 売建可能(D)で **100〜200銘柄**。

> 実際の通過数は Phase 2 で実データ検証する。想定を大きく下回る場合は
> レンジ設定の見直しを検討する（09 未決事項）。

## 2. 株価レンジフィルタ — 通常枠とプレミアム枠

日本株は**単元100株**。株価 P 円の1単元 = **100P 円**。
50万円という資金では、これが銘柄選定の最も厳しい制約になる。

| 枠 | 株価 | 1単元 | 扱い |
|---|---|---|---|
| **通常枠** | **300 〜 2,000円** | 3万〜20万円 | スコア上位から通常採用 |
| **プレミアム枠** | **2,000 〜 3,000円** | 20万〜30万円 | **明確な優位がある場合のみ採用** |
| 対象外 | 300円未満 | — | 1ティック（1円）が0.33%以上。スプレッドコストが相対的に巨大 |
| 対象外 | 3,000円超 | 30万円超 | 1銘柄で資金の60%超。分散が成立しない |

### プレミアム枠がハンデを負う理由

1単元20〜30万円は50万円の **40〜60%を1銘柄が占める**。

- 同時保有が3〜5銘柄から**2〜3銘柄に落ちる**
- ポジションサイズの粒度が粗くなり、リスク管理の精度が下がる

**この集中リスク増を正当化するだけの期待リターン優位が必要。**

### プレミアム枠の採用条件（すべて満たすこと）

1. 日次スコア（§3）が、**通常枠で採用された銘柄のスコア中央値 × 1.3 以上**
2. **同時採用は1銘柄まで**（集中リスクの上限）
3. リスク管理の上限（1銘柄あたり総資産の25%）を超えないこと

> **閾値 1.3倍 は暫定値。** Phase 4 の検証項目として、
> **プレミアム枠の有無で成績を比較し、実際にプラスに寄与しているかを確認する。**
> 寄与しないなら枠ごと削除する。閾値も同時にチューニングする。

### この制約が意味すること

**プライム上位の高株価銘柄（ソニー、キーエンス、東京エレクトロン等）は対象外になる。**
50万円で日本株を自動売買する以上、これは避けられない。

「有名企業を売買する」のではなく、
**「株価帯が資金に合う銘柄の中から統計的に選ぶ」のが本質**。

> 株価レンジは**資金量の関数**。資金が増えれば上限を緩められるので、
> `config/universe.yaml` でパラメータ化しておく。

## 3. Layer 2 — 日次銘柄選定（寄り前 8:00-8:55）

Layer 1 を通過した100〜200銘柄から、**その日実際に監視する50銘柄**を選ぶ
（WebSocket の登録上限が50のため）。

### スコア指標

| 指標 | 内容 | 狙い |
|---|---|---|
| **ATR%** | 14日ATR ÷ 株価 | 日中値幅の期待値。**往復コスト（スリッページ0.1〜0.2%）の5倍以上ないと勝負にならない → ATR% ≥ 2% を要求** |
| **寄り前ギャップ率** | 寄り前気配 vs 前日終値 | 初動のエネルギー |
| **寄り前出来高比** | 寄り前気配の板の厚み ÷ 20日平均出来高 | 当日の注目度の代理変数 |

### 選定手順

1. 各指標を順位に変換し、正規化して加重合計 → スコア
2. **ATR% ≥ 2% を満たさない銘柄はここで落とす**（コスト負けするため）
3. 通常枠からスコア上位を採用
4. プレミアム枠は §2 の条件（中央値 × 1.3、同時1銘柄まで）を満たす場合のみ追加
5. **上位50銘柄を WebSocket に登録**
6. 場中、シグナルが出た **3〜5銘柄にエントリー**

> 登録銘柄の場中の頻繁な入れ替えは避け、**寄り前に確定させる**。
> 入れ替えは `PUT /register` / `PUT /unregister` を消費し、
> 配信の連続性も途切れる。

## 4. 銘柄選定における3つの落とし穴

自動売買の構築で最も失敗が起きやすい箇所。**設計原則として必ず守る。**

### 4.1 銘柄選定ルールも戦略の一部としてバックテストする

「どう選ぶか」はシグナルと同じくらい成績を左右する。
選定ルールを後から調整すると、シグナルの検証結果が汚染される。

**選定ルールとシグナルは同時に固定してから検証する。**

### 4.2 サバイバーシップバイアスの回避

「**現在**プライムに上場している銘柄」で過去を検証すると、
上場廃止・降格した銘柄が母集団から抜け落ち、**成績が構造的に過大評価される**。

J-Quants の上場銘柄一覧は日付指定で取得できるので、
**各時点のユニバースを当時の情報で再構成する**。

### 4.3 ルックアヘッドバイアスの回避

寄り前に選定するなら、使ってよいのは
**前日大引けまでの確定情報と当日の寄り前気配だけ**。

当日の終値や日中データを選定に使うと、
バックテストだけ好成績になり本番で再現しない。

**バックテストエンジン側で、各時点で参照可能なデータを構造的に制限する。**
「気をつける」のではなく「**起こせない**」ようにする。

## 5. 実装マッピング

| 責務 | モジュール |
|---|---|
| Layer 1 ユニバース構築（日次バッチ） | `universe/builder.py` |
| 個別フィルタ（流動性・株価レンジ・信用区分・除外） | `universe/filters.py` |
| Layer 2 日次スコアリング（寄り前・50枠） | `universe/selector.py` |
| 売建可否・空売り価格規制の取得 | `data/shortable.py` |
| 営業日・決算発表日カレンダー | `data/calendar.py` |
| 時点データ制限（ルックアヘッド防止） | `engine/backtest.py` |
| パラメータ（資金量の関数） | `config/universe.yaml` |
