# 09. データ源と2段階構成

**Stage A（口座なし）と Stage B（口座あり）で、使えるデータが変わる。**
本ドキュメントは何が取れて何が取れないかを整理し、
取れないものへの対処を定義する。

---

## 1. 2段階構成

| | Stage A | Stage B |
|---|---|---|
| **口座** | **不要** | 必要（ただし**運用資金は入れない**） |
| **API** | **不要** | kabuステーションAPI |
| データ源 | J-Quants（無料）+ yfinance | 上記 + kabuステーションAPI |
| 内容 | データ基盤・ユニバース・バックテスト・竹の実装・ヒストリカル検証 | ペーパートレード・システム信頼性の検証 |
| 判定 | **戦略に見込みがあるか** | **システムが信頼できるか** |

**Stage A で見込みがなければ、口座を開く必要すらない。**
口座開設・API申込・Windows常設のコストを、戦略の有望性が確認できるまで払わずに済む。

> **口座開設と入金は別。** 口座開設自体は無料・入金不要で、
> kabuステーションAPI も無料。Stage B は「口座は開くが運用資金50万円は入れない」状態。
> ただし Professional プランの条件に信用口座開設と取引実績があるため、
> 最低1回の実取引（数万円程度）が必要な可能性がある（要確認）。

## 2. 口座不要で使えるデータ源

### 2.1 J-Quants API（日本取引所グループ公式）

| 項目 | 内容 |
|---|---|
| 必要なもの | **メールアドレスでのアカウント登録のみ。証券口座は不要** |
| 提供元 | JPX（証券会社ではないため口座の概念がない） |
| 無料プラン | 過去2年分。**ただし12週間遅延** |
| 有料 | Light 1,650円/月〜（直近データ・長い履歴） |
| 認証 | V2 は API キー方式（V1 のリフレッシュトークン方式は廃止済み） |

**取れるもの**: 日足、**日付指定の上場銘柄一覧**、財務、投資部門別売買状況など。

> **日付指定の上場銘柄一覧が取れることが決定的に重要。**
> サバイバーシップバイアスの回避に必須（docs/03-universe.md §4.2）。
> yfinance では代替できない。

**取れないもの**: 分足、板情報、リアルタイム価格。

### 2.2 yfinance（Yahoo Finance）

| 項目 | 内容 |
|---|---|
| 必要なもの | **なし**（ライブラリを入れるだけ） |
| 銘柄指定 | 日本株は `7203.T` のようにサフィックス `.T` |
| 遅延 | 15〜20分（リアルタイムではない） |
| 位置づけ | **非公式API。** 規約・可用性・品質の保証がない |

**取得可能な期間（Yahoo Finance API の制限）**:

| 足 | 遡れる期間 |
|---|---|
| **1分足** | **直近7日** |
| 2分/5分/15分/30分/90分足 | **直近60日** |
| 60分足 | 直近730日 |
| 日足 | 制限なし |

> 本環境（サンドボックス）ではネットワークポリシーにより Yahoo への疎通が
> ブロックされており**実測できていない**。上記は Yahoo Finance API の公開仕様。
> Phase 1 の最初に、実機で必ず実測して確認すること。

### 2.3 これが計画に与えた改善

**現行計画の最大のボトルネックが消える。**

当初は「分足はどこからも取れないので、kabuステーションAPI で3ヶ月かけて
自前蓄積してからでないと竹を検証できない」という制約があった。

**yfinance は5分足を過去60日分まとめて取得できるため、待たずに検証を始められる。**
オープニングレンジ・ブレイクアウト（30分レンジ）の検証には5分足で十分。

1分足は7日窓しかないが、**日次でローリング回収すれば蓄積できる**
（週1回でも足りるが、取りこぼしを考えて日次で回す）。

## 3. 口座なしでは取れないもの

| # | 取れないもの | 影響 | 対処 |
|---|---|---|---|
| 1 | **板情報**（bid/ask/厚み） | 約定モデルが粗くなる | スリッページを**保守的に厚く**見積もる（§4） |
| 2 | **寄り前気配** | Layer 2 スコア3指標のうち2つが使えない | 前日引け時点の情報だけで選定する（§5） |
| 3 | **一般信用デイトレの売建可能銘柄リスト** | 売建可否フィルタが使えない | Stage A は流動性上位で代理。Stage B で実データに差し替え |
| 4 | **発注系の動作** | 大引けクローズ・reconcile・冪等性・レバレッジ強制・レート制限が**未検証** | **Stage B が必要**（§6） |

---

## 4. 約定モデル — 板がない場合の対処

**原則: 検証できないものは、必ず保守的な側（成績が悪くなる側）に倒す。**

| 項目 | Stage A（板なし） | Stage B（板あり） |
|---|---|---|
| 成行の約定価格 | そのバーの**不利な側**（買いは高値寄り、売りは安値寄り）を仮定 | 次ティックの反対サイド気配 |
| 指値の約定判定 | バーのレンジが価格を通過 **かつ** 出来高が十分な場合のみ | 板の通過 + 出来高按分 |
| スリッページ | **厚めに見積もる**（片道 15〜20bps） | 実測値に置換（片道 10bps 前提） |

> **楽観的な約定モデルを使わない。**
> バックテストで勝つ戦略を作るのは簡単だが、それは目的ではない。
> Stage B で実測スリッページに置き換えたときに成績が崩れるなら、
> それは Stage A のモデルが甘かったということ。

## 5. Layer 2 銘柄選定 — 寄り前気配がない場合

当初の Layer 2 スコアは3指標のうち2つが寄り前気配に依存していた。

| 指標 | Stage A | 理由 |
|---|---|---|
| ATR%（14日ATR ÷ 株価） | **使える** | 前日までの日足から計算できる |
| 寄り前ギャップ率 | **使えない** | 寄り前気配が必要 |
| 寄り前出来高比 | **使えない** | 寄り前の板の厚みが必要 |

### Stage A の代替スコア（前日引け時点の情報のみ）

| 指標 | 内容 | 狙い |
|---|---|---|
| **ATR%** | 14日ATR ÷ 株価 | 日中値幅の期待値。**ATR% ≥ 2% は変更なし** |
| **前日出来高比** | 前日出来高 ÷ 20日平均出来高 | 前日に注目が集まったか |
| **前日レンジ%** | (前日高値 − 前日安値) ÷ 前日終値 | ボラティリティの持続性 |
| **前日終値位置** | (終値 − 安値) ÷ (高値 − 安値) | 前日の需給の決着。翌日の初動の方向のヒント |

**この設計は妥協ではない。**
「前日引け時点の情報だけで翌日の監視銘柄を決める」のは実運用でも一般的な方式で、
寄り前気配は流動性が薄くノイズが多いという批判もある。

### Stage B での検証構造

Stage B で寄り前気配が使えるようになったら、**追加して予測力を比較検証する**：

- Stage A スコア単体
- Stage A スコア + 寄り前気配

**寄り前気配が実際に予測力を持つかを実データで判定できる。**
プレミアム枠の寄与検証（docs/03-universe.md §2）と同じ構造。
持たないなら追加しない。

## 6. Stage B を省いた場合に何が起きるか

Stage A の後に Stage B を飛ばして実弾に入ることは技術的には可能。
**ただし以下が未検証のまま本番になる。**

| 未検証項目 | 想定される事故 | 金銭的影響 |
|---|---|---|
| 大引けクローズの信頼性 | 建玉を閉じ損ねる | **1回2,200円**（月利目標の約2日分） |
| 発注の冪等性 | ネットワーク断のリトライで**二重発注** | 意図の2倍の建玉。レバレッジ超過 |
| レバレッジ1倍の強制 | 上限を超えた発注が通る | 最大損失が想定を超える |
| reconcile | 状態のズレを抱えて自動発注を継続 | 把握していない建玉が残る |
| レート制限 | API に弾かれて発注が通らない | 手仕舞いできない |

**合格基準（docs/07-go-live-criteria.md）の「システム障害ゼロ」は、
Stage B なしには判定できない。**

> Stage B を省くかどうかは**人の判断**。
> ただし省く場合は、実弾の初期投入額をさらに小さくする（10万円→3万円など）ことで
> 未検証リスクを金額で抑えることを推奨する。
