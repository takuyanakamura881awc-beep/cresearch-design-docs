## 竹 — デイトレード ロング/ショート（当日決済）★メイン手法

> **【2026-08-24 追記】現行の竹（下記シグナルA+Bの混合）は Phase 3 の
> ランダム検定で棄却が確定した。以下の定義は「何を試して何が分かったか」の
> 記録として残し、削除しない。**
>
> - **シグナルA（ORB順張り）は、順張り・反転どちらの向きでも実データで
>   ランダムエントリーに勝てなかった**（`docs/00` 意思決定ログ38・43）
> - **シグナルB（VWAP乖離逆張り）単独は、多重比較補正した合格基準に
>   僅差で届かなかった**（全期間95.5% < 必要閾値99%）が、前半・後半
>   どちらの期間でもランダムより上という、他の棄却変種にはない特徴があった
>   （意思決定ログ46）
> - **竹という「ORB+VWAP混合」の構造自体、次のエントリー根拠を
>   ゼロから決め直す。** 順張りへの再挑戦は優先度を下げ、逆張りの発想を
>   手がかりの1つとして次の設計に持ち越す
> - 検定コマンド: `scripts/backtest_take.py --experiment` / `--stress-test`。
>   縮小版レジーム診断: `--by-regime`（意思決定ログ47）
> - **レジーム診断の結論（意思決定ログ48〜50）**: 訂正版でVWAP乖離の成績が
>   市場全体の calm/wild で偏る事実は確認できた（calm 73.5% vs wild 99.0%）。
>   ただしそれを前日情報から予測できるか（先読み版フィルタの前提となる
>   「日をまたいだ持続性」）を診断したところ、統計的に有意な差は
>   出なかった（60.0% vs 44.4%、n=20/18、p≈0.34）。**否定ではなくデータ
>   不足による判定不能**という位置づけで、市場全体レジームに基づく
>   先読みフィルタ化はここで一区切り。80営業日に近づけば同じ診断を
>   より大きな母数で再実行する余地を残す
> - **VWAP乖離の2方向拡張も棄却（意思決定ログ51・52）**: 乖離下限を
>   2.0%まで厳しくする変種、1.5%+出来高確認1.5倍の変種を追加検定した。
>   どちらも既存の1.5%単独（95%）を上回れず（2.0%→65%、出来高確認→50%）、
>   「厳しくするほど良くなる」という単調な傾向は2.0%で反転した。VWAP乖離
>   という手がかりはこの2方向で使い切ったと判断
> - **ギャップ・フェードも棄却（意思決定ログ53〜56）**: 日足2年分
>   （63,900ペア）で、閾値を上げるほどフェード側へ振れる傾向は
>   一貫して観測でき、t値3.2〜4.9で統計的にも本物だった。**しかし
>   全バケットで net が負**（最良の2.0%でも gross +15.7bps に対し
>   コスト30bps、net -14.4bps）
> - **3実験を通じて分かったのはコスト構造の問題（意思決定ログ56）**:
>   竹（gross ≈ -0.3bps）・VWAP乖離単独（≈ +10bps）・ギャップフェード
>   （≈ +16bps）に対し、コストは常に30〜44bps。**優位 0〜16bps vs
>   コスト 30〜44bps という比率がすべての実験で一定**。個々のシグナルの
>   良し悪しではなく、コスト構造そのものが効いている
> - **シグナルではなくコストの前提を検証した（意思決定ログ57〜60）**:
>   `tick.DEFAULT_SPREAD_TICKS = 2.0` がプロジェクト最大の当て推量で、
>   全コスト計算を線形にスケールする。日足だけで実効スプレッドを
>   推定する Corwin-Schultz を `src/autotrader/spread.py` に実装したが、
>   **この銘柄群ではノイズ床に埋もれて推定不能**（プールしても-1.3bps）。
>   ただし「測れない」で止めず感度分析を行い、**スプレッド想定を
>   0.5〜2.0本のどこに置いても竹・VWAP乖離は一度も net 正にならない**
>   ことを確認した。**問題はコストの見積り精度ではない**
> - **呼値そのものを変える方向が効いた（意思決定ログ61〜67）**:
>   東証の呼値は TOPIX100 だけ細かい（0.1〜0.5円）。その銘柄群で
>   ギャップ・フェードを測り直すと、**プロジェクト初の net 正**になった
>   （2.0%バケットで gross +24.21bps / コスト 4.75bps / **net +19.46bps**、
>   t=8.0、63,900ペア規模）。サバイバーシップを外しても数字はほぼ動かない
> - **細かい呼値は必要条件（意思決定ログ67）**: 同じ銘柄・同じ日を
>   通常銘柄の呼値（1円）で評価し直すとコストが4.75→21.09bps になり、
>   2.0%バケット以外はすべて net 負になる。**「株価が高い銘柄を扱える」
>   だけでは足りず、TOPIX100 であること自体が要る**
> - **建玉シミュレーションでも目標未達（意思決定ログ69）**: TOPIX100 99銘柄の
>   うち92銘柄が株価上限1,250円（`資金50万円 × 25% ÷ 100株`）を超えるため、
>   資金を振ってみると月利は 50万→+1.28% / 120万→+3.69% / 200万→**+3.91%（最大）**
>   / 300万→+2.81%。**損切り・ブレーカー・5分足の約定モデルを含まない
>   上限見積りでこの水準**であり、目標+5%に届かない
> - **市場ドリフトを控除すると優位の86%が消えた → 棄却（意思決定ログ71）**:
>   方向別では買建（ギャップダウンのフェード）が +35.95bps と単調に伸びたが、
>   その日の全銘柄の平均 `始値→終値` を差し引くと **+4.94bps** まで落ちた。
>   逆算すると**ある銘柄が2%以上ギャップダウンした日、市場全体がその日
>   およそ31bps 上昇して引けている**。実在する現象だが、銘柄固有の平均回帰ではなく
>   **市場全体への方向性の賭け**であり、レバレッジ1倍・市場中立に近い設計とは別物
> - **t値は件数ベースだと過大だった（意思決定ログ72）**: 同じ日の銘柄は市場要因で
>   強く相関しているので、独立な観測は件数（5,786件）ではなく**日数ぶんしかない**。
>   `clustered_stats` で日クラスタの t値を出すように直した
> - **棄却されずに残った資産**: TOPIX100 の呼値がコストを1桁下げること
>   （21.09 → 4.75bps）は市場の制度であって仮説ではないので、次の手法にもそのまま効く。
>   `capacity_stats`（bps → 月利の翻訳）と診断の道具立て（ランダム検定・多重比較補正・
>   期間分割・サバイバーシップ回避・市場ドリフト控除・日クラスタ t値）も手法に依存しない

### 概要

| | |
|---|---|
| **銘柄選定** | 03-universe.md のスコアリングで日次50銘柄 → シグナル発生3〜5銘柄にエントリー |
| **保有期間** | 数十分〜大引け前（**当日決済必須**） |
| **信用区分** | **デイトレ信用（手数料0・金利0・貸株料0）** |
| **ポジション** | 同時3〜5銘柄、各6〜12.5万円。**1日12〜13トレード**（実測。1銘柄1日1回まで） |
| **期待成績** | 年利 20〜50% / 最大DD 15〜30% |
| **必要データ** | 分足。**Stage A は yfinance の5分足（過去60日分が即座に取れる）**、Stage B は kabuステーションAPI |
| **板情報** | **シグナルには使わない**（下記「板情報の扱い」）。執行と Stage B の品質フィルタでのみ使う |

### なぜメインなのか

- **コスト0** — デイトレ信用は手数料・金利・貸株料すべて0
- **資金効率が最大** — 同一銘柄を1日に何度でも回転できる
- **オーバーナイトリスクなし** — 当日決済。1トレードのテールリスクがスイングより小さい
- **相場環境への依存が小さい** — ロング/ショート両建て

「資金効率が良い方法を選びたい」という要求に最も直接的に応える。

### 1日のトレード数について（実測で修正）

当初は「1日5〜15トレード」と書いていたが、**資金50万円ではそこまで回せない**。

**1単元100株が最小単位なので、1敗のインパクトはこれ以上小さくできない。**

| 株価 | 1単元 | 資金比 | ATR3%での1敗 | ATR5%での1敗 |
|---:|---:|---:|---:|---:|
| 300 | 30,000 | 6% | -0.27% | -0.45% |
| 700 | 70,000 | 14% | -0.63% | -1.05% |
| 900 | 90,000 | 18% | -0.81% | -1.35% |
| 1,250 | 125,000 | 25% | -1.12% | -1.88% |

実測（2026-05-29）で選定された50銘柄の1敗インパクトは
**中央値 -0.99% / 最悪 -1.86%**（シャープ 622円・ATR 5.00%・建玉が資金の25%）。

**日次ブレーカー（-2%、`docs/05` #4）は損益で判定するのであって敗数ではない。**
利確2.5×ATR / 損切1.5×ATR なので、1勝が約1.7敗を打ち消す::

    1勝2敗 → -0.5×ATR   まだ耐えられる
    1勝3敗 → -2.0×ATR   ブレーカー圏
    2勝3敗 → +0.5×ATR   まだ耐えられる

つまり**勝ちを挟まずに2連敗すると当日が終わる**。勝ちが挟まればもっと回せる。
それでも#### 実測: 1日12〜13回で日次ブレーカーは0日

実データ（39営業日）で回したところ **1日12.7〜13回**、
そして**日次ブレーカーの発動は0日**だった。勝ちが挟まるので -2% に届かない。

一時この欄を「1日3〜5トレード」としたが、**あれは全敗を仮定した最悪値**で、
実際の分布ではない。訂正の経緯を残しておく:

| | 根拠 | 位置づけ |
|---|---|---|
| 5〜15 | 実測前の見込み | 未検証 |
| 3〜5 | 勝ちを挟まない最悪値からの逆算 | **仮定が厳しすぎた** |
| **12〜13** | **実データ39営業日の実測** | 現状の値 |

**トレード数は制約ではなく結果。** 縛っているのは日次損益 -2% であって
回数ではない。回数を目標にすると、勝てる場面を見送るか
無理に回すかのどちらかになる。

回転を抑える仕組みは入れてある（下記の再エントリー制御）。
妥当な水準は Phase 4 のウォークフォワードで確定する。

#### 再エントリー制御

**損切りした銘柄には、その日もう入らない**（`reenter_after_stop=False`）。
損切りは「その日のその仮説が外れた」証拠であり、
新しい情報なしに同じ賭けを繰り返すのはコストを払うだけ。

制御を入れる前は損切り直後にシグナルAが再発火して入り直す往復が起き、
**1日28.6回**まで膨らんでいた（損切り83件の多くがこの往復）。
入れた後は12.7回。

1銘柄あたり1日1回を既定にしている（`max_entries_per_symbol_per_day=1`）。
利確なら仮説が機能したので再発火を認めうるが、無制限にはしない。
**暫定値。** Phase 4 で「許す/許さない」の成績を比較して確定する。

ATRベースのサイジング（1敗を資金の0.5%に固定する方式）も検討したが、
**単元100株の粒度に負けて成立しなかった** — 最安の1単元でも予算を超え、
実測の上位10銘柄すべてが0株になった（意思決定ログ25）。

> **月利5〜10%の目標はここでは動かさない。** 届くかどうかは Phase 3 の
> バックテストで測る。目標を先に下げると、戦略が悪いのか前提が悪いのかを
> 切り分けられなくなる。

### シグナルA — オープニングレンジ・ブレイクアウト（順張り）

```
9:00-9:30 の高値/安値でレンジを定義
  ↓
レンジ上抜け → ロングエントリー
レンジ下抜け → ショートエントリー
  ↓
ストップ: レンジ反対側 または エントリー価格 - N×ATR
利確:     エントリー価格 + M×ATR
時間切れ: 14:50 に無条件クローズ
```

寄り付き後30分のレンジは、その日の需給の綱引きの結果。
それを抜けることは新しい方向へのエネルギーを示す、という仮説に立つ。

### シグナルB — VWAP乖離の平均回帰（逆張り）

```
価格が VWAP から一定以上乖離
  かつ 乖離が拡大から縮小に転じた
  ↓
VWAP 方向へエントリー（上方乖離ならショート、下方乖離ならロング）
  ↓
利確: VWAP タッチ
ストップ: 乖離がさらに拡大した水準
時間切れ: 14:50 に無条件クローズ
```

VWAP は機関投資家の執行基準になりやすく、そこへの回帰力が働く、という仮説。

> **シグナルAとBは方向が逆になる場面がある。** 同一銘柄で両方が
> 同時発火した場合はエントリーを見送る（矛盾するシグナルは情報がない状態と扱う）。

### 手仕舞い規律

| 条件 | 動作 |
|---|---|
| ATRベースの逆指値ストップ | 建玉ごとに必ず設定。**ショートは特に必須** |
| 利確目標到達 | クローズ |
| **14:50** | **無条件で全建玉を成行クローズ**（02-margin-rules.md §3） |
| 日次損失上限 -2% | 当日全停止 + 全建玉クローズ |

### 正直な評価

自宅回線 → localhost API → 証券会社という経路のレイテンシでは、
専用線とコロケーションを持つ機関投資家との板の取り合いに勝つのは難しい。
**薄い利幅を狙う手法ほどレイテンシ劣位が効く。**

**竹の実績とレイテンシ実測を見てから着手を判断する。**
優先度は最も低く置く。

## 梅 — 日足スイング ロング/ショート／資金300万円以上で追加

| | |
|---|---|
| **銘柄選定** | クロスセクショナル・モメンタム（過去60〜120日リターンのランキング） |
| **保有期間** | 5〜20営業日（オーバーナイト保有）、週次リバランス |
| **信用区分** | 一般信用（長期）※デイトレ信用は当日決済必須のため使えない |
| **コスト** | **金利・貸株料が発生**（デイトレ信用と違い無料ではない） |
| **期待成績** | 年利 5〜15% / 最大DD 10〜20% |
| **必要データ** | 日足のみ → J-Quants 無料プランで検証可能 |
| **追加条件** | **資金300万円以上**（目安） |

### なぜ資金300万円を条件にするのか

梅は**分散が効いてこそ機能する**手法。

50万円では上位3ロング + 下位2ショートが限界（1銘柄10万円）。
株価レンジの制約（03-universe.md §2）も重なり、
**モメンタム上位から選べる銘柄が大幅に減って戦略の前提が崩れる**。

資金が増えれば**分散数と株価レンジ上限の両方が緩み**、梅が本来の性能を発揮できる。

### 竹との併用

竹（日中・当日決済）と梅（スイング・オーバーナイト）は**時間軸が異なるため併用可能**。
資金配分を分ければ互いのポジションが干渉しない。

ただし**レバレッジ1倍の不変条件は両手法の合計に対して適用する**。
竹の建玉 + 梅の建玉 ≤ 現金残高。

## 板情報の扱い

**「デイトレードなのになぜ板を見ないのか」への回答。** シグナルと執行を分けて整理する。

### 竹は板を「シグナル」に使わない

竹のシグナル（オープニングレンジ・ブレイクアウト、VWAP乖離）は
**5分足の OHLCV だけで計算でき、板情報を必要としない**。これは意図的な設計判断。

**理由1: 時間軸が合わない（本質）**

板の厚みや指値の偏りが価格を予測するのは**数秒〜数分**のスケール。
竹の保有期間は数十分〜大引けなので、**エントリー時点の板の状態は数十分後にはほぼ無関係**になる。

逆に言えば、板を主シグナルにするなら保有期間も数分にすべきで、それはもう松（スキャルピング）。
**板を使う手法と、板を使わず数十分持つ手法は別物**で、混ぜると中途半端になる。

**理由2: 板を見る手法ほどレイテンシ勝負になり、個人が構造的に不利**

自宅回線 → localhost API → 証券会社という経路では、専用線とコロケーションを持つ
機関投資家に勝てない。**板を読んでから発注するまでの間に、相手はもう動いている。**
薄い利幅を狙う手法ほどこの劣位が効く。松を後回しにする判断の根拠でもある。

**理由3: Stage A では板が取れない**

口座なしでは検証できない。ただしこれは3番目の理由で、1と2が本質。
**板が取れる環境でも竹には使わない。**

### 板は「執行」には効いており、既に設計に入っている

シグナル判断に使わなくても、発注時には板が効く。対応関係は以下の通り。

| 板への配慮 | 実装箇所 |
|---|---|
| 10〜15万円の注文が板を動かさない水準の確保 | `universe/filters.py` フィルタB（20日平均売買代金10億円以上） |
| 板がない前提の保守的な約定モデル（片道20bps） | `broker/replay.py`、`config/strategies.yaml` の `execution_cost.stage_a` |
| 実測の板を使う約定モデル（片道10bps） | `broker/paper.py`、`config/strategies.yaml` の `execution_cost.stage_b` |

### Stage B で板を「エントリー品質フィルタ」として足し、比較検証する

板をシグナルの主役にはしないが、**エントリーの品質フィルタ**としてなら竹の時間軸でも効きうる：

- ブレイクアウト時に板が薄い → 見せ板・流動性不足の可能性 → **見送る**
- 反対側の板が厚い → ブレイクが失敗しやすい → **見送る**
- 成行のインパクト推定 → **発注サイズを調整する**

**足して成績が上がるかを実データで判定する。**
寄り前気配（`docs/09-data-sources.md` §5）・プレミアム枠（`docs/03-universe.md` §2）と
同じ検証構造。**上がらなければ足さない。**

設定は `config/strategies.yaml` の `take_intraday.orderbook_filter`（既定 `enabled: false`）。
実装は Stage B（Phase 4）。

## 実装方針

`strategy/base.py` に抽象インターフェースを置く。
